# 手动安装与使用：CLIProxyAPI + Codex Plus 接入 Claude Code

## 这套方案做什么

把 Codex Plus 账号通过 CLIProxyAPI 转成 Claude Code 能调用的本地 Anthropic-compatible API。

Claude Code 最终访问：

```text
http://127.0.0.1:8317
```

你只需要维护两类配置：

| 用途 | 文件 |
|---|---|
| CLIProxyAPI 服务、代理端口、上游连接 | `C:\Users\<用户名>\.cli-proxy-api\config.yaml` |
| Claude Code 使用哪个 API 和模型 | `C:\Users\<用户名>\.claude\settings.json` |

不需要再改 `env.nu`。

---

## 1. `config.example.yaml` 有什么用

`C:\Users\<用户名>\.cli-proxy-api\config.example.yaml` 是 **完整示例配置/参考模板**。

它的作用：

- 查看 CLIProxyAPI 支持哪些字段。
- 忘记配置格式时复制其中一段。
- 配置损坏时参考它恢复默认结构。

它不是运行时必需文件。CLIProxyAPI 实际读取的是：

```text
C:\Users\<用户名>\.cli-proxy-api\config.yaml
```

如果你启动时没有指定 `-config`，程序会从当前工作目录找 `config.yaml`。所以建议始终用：

```powershell
cli-proxy-api.exe -config "%USERPROFILE%\.cli-proxy-api\config.yaml"
```

---

## 2. 安装目录

建议统一放在：

```text
C:\Users\<用户名>\.cli-proxy-api\
```

最终结构：

```text
.cli-proxy-api\
├── cli-proxy-api.exe
├── config.yaml
├── config.example.yaml          # 可选，参考模板
├── codex-xxx-plus.json          # Codex OAuth 登录文件
├── logs\
└── static\management.html       # 管理页面文件
```

## 3. 下载 CLIProxyAPI

打开：

```text
https://github.com/router-for-me/CLIProxyAPI/releases
```

下载 Windows x64 / amd64 版本，把 `cli-proxy-api.exe` 放到：

```text
C:\Users\<用户名>\.cli-proxy-api\cli-proxy-api.exe
```

手动更新 CLIProxyAPI 时：

1. 先停止正在运行的 CLIProxyAPI。
2. 下载最新 Windows x64 / amd64 release。
3. 备份旧的 `cli-proxy-api.exe`。
4. 用新文件替换 `C:\Users\<用户名>\.cli-proxy-api\cli-proxy-api.exe`。
5. 重新启动，并执行 CodexToClaude 的 `restart` 和 `verify` 做验收。

如果使用 CodexToClaude GUI 或 CLI，可以直接执行 `cliproxy-update` 自动完成停服、下载、备份、替换和恢复启动。

## 4. 创建 `config.yaml`

路径：

```text
C:\Users\<用户名>\.cli-proxy-api\config.yaml
```

推荐最小配置：

```yaml
host: "127.0.0.1"
port: 8317
proxy-url: "http://127.0.0.1:7897"

remote-management:
  allow-remote: false
  secret-key: ""
  disable-control-panel: false

auth-dir: "~/.cli-proxy-api"

api-keys:
  - "sk-cliproxy-local-dev-2026"

passthrough-headers: true

codex-header-defaults:
  user-agent: 'codex_cli_rs/0.114.0 (Mac OS 14.2.0; x86_64) vscode/1.111.0'

quota-exceeded:
  switch-project: true
  switch-preview-model: true

request-retry: 1
max-retry-credentials: 1
max-retry-interval: 5
# CLIProxyAPI v7.1.61+ 会在文件日志中记录 Codex backend request IDs，便于排查上游请求。
debug: true
logging-to-file: true
logs-max-total-size-mb: 10
error-logs-max-files: 5
```

### 修改 VPN 代理端口和协议

如果你的代理端口不是 `7897`，只改这一行：

```yaml
proxy-url: "http://127.0.0.1:7897"
```

例如改成 `7890`：

```yaml
proxy-url: "http://127.0.0.1:7890"
```

如果 HTTP 代理在 Codex 上游请求中经常出现 TLS handshake timeout、`context canceled`、30 秒左右超时或长时间无响应，可以改为同端口 SOCKS5：

```yaml
proxy-url: "socks5://127.0.0.1:7890"
```

如果使用 CodexToClaude GUI/CLI，推荐选择 `ProxyMode = Auto` 并填写 `127.0.0.1:7890`；工具会先按 HTTP 写入，`verify` 和后台 watchdog 遇到超时或长请求卡住时可在同地址 HTTP/SOCKS5 间切换，并在短时间多次卡住后临时固定到更少超时的一侧。CLIProxy 登录/配置后会为 enabled Codex OAuth JSON 补齐缺失的 `websockets: true`，保留已有显式值。若日常压测仍有超时，建议显式选择 `ProxyMode = Http` 或 `ProxyMode = Socks5` 固定使用更稳定的协议。

如果无需代理，请删除 `proxy-url` 这一行；使用 CodexToClaude GUI/CLI 时选择 `ProxyMode = Direct`。

`codex-header-defaults.user-agent` 是 Codex OAuth 上游请求的 UA fallback。遇到 `chatgpt.com/backend-api/codex/responses` 返回 Cloudflare challenge 时，先确认该字段存在；如果存在仍 403，再换代理出口或网络。

改完后必须重启 CLIProxyAPI。

## 5. 登录 Codex Plus

在 PowerShell 执行：

```powershell
& "$env:USERPROFILE\.cli-proxy-api\cli-proxy-api.exe" -config "$env:USERPROFILE\.cli-proxy-api\config.yaml" -codex-login
```

如果普通 OAuth 登录不方便，可以试设备码：

```powershell
& "$env:USERPROFILE\.cli-proxy-api\cli-proxy-api.exe" -config "$env:USERPROFILE\.cli-proxy-api\config.yaml" -codex-device-login
```

登录完成后确认根目录下有 Codex JSON：

```powershell
Get-ChildItem "$env:USERPROFILE\.cli-proxy-api" -Filter "*.json"
```

如果文件在：

```text
C:\Users\<用户名>\.cli-proxy-api\auths\
```

请复制到：

```text
C:\Users\<用户名>\.cli-proxy-api\
```

因为当前使用方式要求 OAuth JSON 在 `auth-dir` 根目录。

## 6. 启动 CLIProxyAPI

### 方式 A：PowerShell 前台启动

```powershell
& "$env:USERPROFILE\.cli-proxy-api\cli-proxy-api.exe" -config "$env:USERPROFILE\.cli-proxy-api\config.yaml"
```

窗口不能关，关闭窗口服务就停。

### 方式 B：PowerShell 后台启动

```powershell
Start-Process -FilePath "$env:USERPROFILE\.cli-proxy-api\cli-proxy-api.exe" -ArgumentList @("-config", "$env:USERPROFILE\.cli-proxy-api\config.yaml") -WorkingDirectory "$env:USERPROFILE\.cli-proxy-api"
```

### 方式 C：双击 exe

可以双击，但不如上面稳定。

原因：CLIProxyAPI 默认会从“当前工作目录”找 `config.yaml`。如果双击时工作目录正好是：

```text
C:\Users\<用户名>\.cli-proxy-api
```

通常能启动；如果工作目录不是这个目录，就可能报：

```text
failed to read config file: open ...\config.yaml: The system cannot find the file specified
```

### 推荐做法：创建 `start-cliproxyapi.bat`

在任意位置新建 bat：

```bat
@echo off
cd /d "%USERPROFILE%\.cli-proxy-api"
cli-proxy-api.exe -config "%USERPROFILE%\.cli-proxy-api\config.yaml"
pause
```

以后双击这个 bat，比直接双击 exe 更稳。

## 7. 停止 CLIProxyAPI

如果是前台窗口启动，按：

```text
Ctrl+C
```

如果是后台进程，PowerShell 执行：

```powershell
Get-NetTCPConnection -LocalPort 8317 -ErrorAction SilentlyContinue |
  Select-Object -ExpandProperty OwningProcess -Unique |
  ForEach-Object { Stop-Process -Id $_ -Force }
```

## 8. 配置 Claude Code 使用 CLIProxyAPI

编辑：

```text
C:\Users\<用户名>\.claude\settings.json
```

把 `env` 改成类似这样：

```json
{
  "env": {
    "ANTHROPIC_AUTH_TOKEN": "sk-cliproxy-local-dev-2026",
    "ANTHROPIC_BASE_URL": "http://127.0.0.1:8317",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "gpt-5.5",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "gpt-5.4",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "gpt-5.4",
    "ANTHROPIC_DEFAULT_OPUS_MODEL_NAME": "gpt-5.5",
    "ANTHROPIC_DEFAULT_SONNET_MODEL_NAME": "gpt-5.4",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL_NAME": "gpt-5.4",
    "ENABLE_TOOL_SEARCH": "true"
  }
}
```

如果 Claude Code 在当前代理模型下误判上下文窗口，导致自动压缩触发过晚，可以可选添加：

```json
"CLAUDE_CODE_AUTO_COMPACT_WINDOW": "120000",
"CLAUDE_AUTOCOMPACT_PCT_OVERRIDE": "70"
```

这只是影响 Claude Code 的近似自动压缩触发计算；实际触发时机仍由 Claude Code 决定。要禁用自定义阈值 override，请删除这两个 env，而不是写空字符串。

如果你的 `settings.json` 还有其它字段，例如 `statusLine`、`permissions`、`language`，不要删，只替换 `env` 里面相关字段。

自定义 `ANTHROPIC_BASE_URL` 下，Claude Code 默认会关闭 ToolSearch；CodexToClaude 会显式设置 `ENABLE_TOOL_SEARCH=true`，以便在当前已验证的 CLIProxyAPI 链路上启用按需工具加载。若升级 provider 后怀疑 ToolSearch 兼容性异常，可先运行 `verify -CheckToolSearch` 定位，必要时临时改回 `false` 排查。CLIProxy 路径也不要设置 `CLAUDE_CODE_EFFORT_LEVEL`，脚本会移除它，让 Claude Code 当前 `/effort` 或 `effortLevel` 决定请求语义。若遇到 thinking 输出过长或 TUI 展示异常，可参考 README 中的手动 `payload.filter` 回退配置。

建议删除旧服务遗留字段，例如：

```json
"ANTHROPIC_MODEL": "deepseek-v4-pro"
```

避免它覆盖默认模型选择。

## 9. 修改 Claude Code 使用的 Codex 模型

还是改：

```text
C:\Users\<用户名>\.claude\settings.json
```

常用字段：

```json
"ANTHROPIC_DEFAULT_OPUS_MODEL": "gpt-5.5",
"ANTHROPIC_DEFAULT_SONNET_MODEL": "gpt-5.4",
"ANTHROPIC_DEFAULT_HAIKU_MODEL": "gpt-5.4"
```

可用模型示例：

```text
gpt-5.5
gpt-5.4
gpt-5.4-mini
gpt-5.4
gpt-5.4
gpt-5.2
```

思考等级后缀：

```text
(low)
(medium)
(high)
(xhigh)
```

例如：

```json
"ANTHROPIC_DEFAULT_SONNET_MODEL": "gpt-5.4(high)"
```

改完后重启 Claude Code。

## 10. 验证是否可用

### 检查服务是否启动

```powershell
Invoke-WebRequest -Uri "http://127.0.0.1:8317/healthz" -UseBasicParsing
```

### 检查模型列表

```powershell
$headers = @{ Authorization = "Bearer sk-cliproxy-local-dev-2026" }
Invoke-RestMethod -Uri "http://127.0.0.1:8317/v1/models" -Headers $headers
```

### 检查 Claude Code 请求格式

```powershell
$headers = @{
  "x-api-key" = "sk-cliproxy-local-dev-2026"
  "anthropic-version" = "2023-06-01"
  "Content-Type" = "application/json"
}

$body = @{
  model = "gpt-5.4"
  max_tokens = 20
  messages = @(
    @{ role = "user"; content = "say hi in one word" }
  )
} | ConvertTo-Json -Depth 10

Invoke-RestMethod -Uri "http://127.0.0.1:8317/v1/messages" -Method Post -Headers $headers -Body $body
```

看到返回 `Hi` 就说明 CLIProxyAPI 基础链路正常。

如果使用 CodexToClaude CLI，可以额外显式检查高级 Anthropic-compatible 能力：

```powershell
.\scripts\CodexToClaude.ps1 verify -CheckTools
.\scripts\CodexToClaude.ps1 verify -CheckToolSearch
.\scripts\CodexToClaude.ps1 verify -CheckPromptCaching
```

这些检查不会默认运行；部分 provider 或模型可能不支持 `tool_use`、`tool_result`、ToolSearch 或 prompt caching usage 字段。

如果 Claude Code 报 `thinking options type cannot be disabled when reasoning_effort is set`，表示请求同时携带 `reasoning_effort` 且显式禁用了 `thinking`。优先检查 `cli-proxy-api\config.yaml` 是否有遗留 `payload.filter` 或其它请求改写触碰 `thinking` / `reasoning` / `reasoning_effort`；默认 CodexToClaude 配置不会生成该组合。移除遗留过滤后重启并重新验证。

## 11. Web 管理页面

页面地址：

```text
http://127.0.0.1:8317/management.html
```

本机测试时页面可以打开，标题为：

```text
CLI Proxy API Management Center
```

但当前配置中：

```yaml
remote-management:
  secret-key: ""
```

这会禁用 `/v0/management/*` 管理 API。结果是：

- 页面文件能打开。
- 但管理接口可能不可用。
- 不建议依赖这个 Web 页面管理本地配置。

目前最稳方式仍然是手动编辑：

```text
~/.cli-proxy-api/config.yaml
~/.claude/settings.json
```

## 12. 常见错误处理

### 1. `context canceled`

通常是上游网络连接失败。

检查：

- VPN/代理是否开着。
- `config.yaml` 的 `proxy-url` 端口是否正确。
- 如果使用 HTTP 代理反复超时，改成同端口 `socks5://...` 后重启再试。
- 改完代理端口后是否重启 CLIProxyAPI。

### 2. `Missing API key`

请求 CLIProxyAPI 时没带本地 key。

检查 Claude Code：

```json
"ANTHROPIC_AUTH_TOKEN": "sk-cliproxy-local-dev-2026"
```

检查手动请求是否带了：

```text
Authorization: Bearer sk-cliproxy-local-dev-2026
```

或：

```text
x-api-key: sk-cliproxy-local-dev-2026
```

### 3. `insufficient_quota`

通常说明请求走到了 OpenAI Platform API，而不是 Codex Plus OAuth。

处理：

- 不要使用 `openai-compatibility` 路线。
- 确保 Codex OAuth JSON 启用。
- 确保 `/v1/messages` 日志里使用的是 `provider=codex`。

日志位置：

```text
C:\Users\<用户名>\.cli-proxy-api\logs\main.log
```

### 4. `/v1/models` 为空

通常是 Codex OAuth JSON 没被扫描到。

处理：

- 把 `codex-xxx-plus.json` 放到 `~/.cli-proxy-api` 根目录。
- 确认 JSON 中没有 `"disabled": true`。
- 重启 CLIProxyAPI。

### 5. Claude Code 仍然走旧模型服务

检查：

```text
C:\Users\<用户名>\.claude\settings.json
```

确保：

```json
"ANTHROPIC_BASE_URL": "http://127.0.0.1:8317"
```

`settings.json` 的优先级高于 `env.nu`，所以不要只改 shell 环境变量。

## 13. 最简日常使用清单

### 开启

1. 打开 VPN/代理。
2. 启动 CLIProxyAPI。
3. 打开 Claude Code。

### 关闭

1. 关闭 Claude Code。
2. 停止 CLIProxyAPI。

### 改代理端口

1. 改 `~/.cli-proxy-api/config.yaml` 的 `proxy-url`。
2. 重启 CLIProxyAPI。

### 改模型

如果使用 CodexToClaude GUI，可以在 `Claude 模型` 区修改 Opus、Sonnet、Haiku 模型并保存。

CLI 方式：

```powershell
.\scripts\CodexToClaude.ps1 configure-models -OpusModel "gpt-5.5" -SonnetModel "gpt-5.4" -HaikuModel "gpt-5.4"
```

纯手动方式：

1. 改 `~/.claude/settings.json` 的 `ANTHROPIC_DEFAULT_*_MODEL`。
2. 重启 Claude Code。
3. 执行 `verify` 或实际发起一次 Claude Code 请求确认模型可用。
